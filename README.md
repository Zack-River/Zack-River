## &nbsp;About

I'm **Abdallah Wageeh**, a Full Stack Engineer based in Egypt — operating under the **Zack River** brand.

I build production-ready software with an emphasis on backend engineering, system architecture, and developer experience. I think in systems, not features. My work spans SaaS products, API platforms, and end-to-end client solutions — from schema design to deployment.

I'm not interested in shipping code that works once. I care about building things that hold up.

<br/>

## &nbsp;Engineering Philosophy

> *Software should be simple to use and difficult to build.*

The gap between a working prototype and a production-grade system is where most complexity lives. I focus on that gap. This means thinking about failure modes before happy paths, designing database schemas before writing routes, and treating maintainability as a feature — not an afterthought.

I don't separate "backend work" from "product thinking." Good architecture decisions are product decisions. A poorly designed API creates friction for every developer who touches it. A poorly normalized schema accumulates debt that slows down every feature that follows.

<br/>

## &nbsp;Architecture Mindset

<table>
<tr>
<td width="50%" valign="top">

**Clean Architecture**
Services own their domain logic. No business rules buried in controllers or leaking into the database layer.

**Scalable APIs**
Versioned, contract-first, and designed to be consumed by systems you haven't built yet.

**Database Design**
Schemas are written to last. Indexes are planned, not added reactively. Migrations are never destructive.

</td>
<td width="50%" valign="top">

**Developer Experience**
Readable code, predictable structure, and documentation that doesn't go stale. The next engineer should be able to navigate a codebase without a tour.

**Performance by Default**
Query planning, caching strategy, and connection pooling aren't optimizations I add later — they're part of the initial design.

**Security at Every Layer**
Authentication, authorization, input validation, and rate limiting are built in — not bolted on.

</td>
</tr>
</table>
